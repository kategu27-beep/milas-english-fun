# Mila’s English Fun

Это готовый самостоятельный сайт для ребёнка 8–10 лет, который тренирует простой английский по трём темам: School, Family и Food. Ребёнок общается с доброжелательной Милой, получает короткие подсказки и собирает наклейки. В детском интерфейсе используется только английский язык.

## Как всё устроено

Браузер показывает файлы из папки `public`. Сервер `server.js` принимает ответы, безопасно обращается к Kie.ai и сохраняет прогресс в SQLite. Регистрация не нужна: при первом открытии браузер создаёт случайный анонимный UUID в `localStorage` под именем `mila_user_id`. Если очистить данные браузера или открыть сайт на другом устройстве, посетитель будет считаться новым.

- **Codex** создаёт и изменяет код проекта, запускает проверки и может подготовить новый коммит.
- **GitHub** хранит исходные файлы и историю изменений; Bothost забирает проект из GitHub.
- **Bothost** запускает сервер в интернете и выдаёт HTTPS-домен.
- **Kie.ai** генерирует короткие ответы Милы после первого ответа ребёнка. Первое сообщение и финал занятия создаются локально без оплаты API.

Главные файлы: `server.js` запускает сайт; `src/` содержит базу, диалоги и Kie-интеграцию; `public/` — интерфейс и рисунки; `test/` — автоматические проверки; `.env.example` — пример настроек. База не попадает в GitHub.

## Запуск на компьютере

1. Установите Node.js 20 LTS с сайта nodejs.org (обычная установка с настройками по умолчанию).
2. Откройте терминал в папке проекта.
3. Выполните `npm install`.
4. Скопируйте `.env.example` в файл `.env`.
5. Для бесплатной проверки укажите в `.env` строку `MOCK_AI=true`.
6. Выполните `npm start` и откройте `http://localhost:3000`.
7. Проверки запускаются командой `npm test`.

В PowerShell mock-режим можно включить на один запуск так: `$env:MOCK_AI='true'; npm start`. Он не обращается к Kie и позволяет полностью пройти все темы и получить наклейки.

## Kie.ai

Зарегистрируйтесь на Kie.ai, откройте раздел API Keys и создайте ключ. Для локального запуска вставьте его **только** в локальный `.env`:

```text
KIE_API_KEY=ваш_секретный_ключ
KIE_MODEL=gpt-5-6-luna
MOCK_AI=false
```

Файл `.env` уже исключён через `.gitignore`: секрет нельзя публиковать или коммитить в GitHub. На Bothost ключ добавляется в разделе переменных окружения, а не в файлы репозитория. Если внешний API недоступен из контейнера, включите у проекта опцию исходящих запросов с зарубежного IP (Foreign IP) и перезапустите контейнер.

## Развёртывание на Bothost

1. Загрузите репозиторий на GitHub и создайте в Bothost новый проект из этого репозитория.
2. Если сервис требует выбрать платформу, разрешается выбрать **Telegram** и указать выданный/временный токен. Это только требование панели Bothost: сайт не использует Telegram, а переменная `BOT_TOKEN` полностью игнорируется.
3. Тип приложения: **Node.js**. Runtime: **Node.js 20**. Образ: **Node.js 20 Debian Slim**.
4. Ветка репозитория: обычно `main` (либо фактическая ветка с этим коммитом).
5. Команда запуска: `npm start`. Порт: `3000`. Веб-домен направьте на этот порт.
6. Создайте постоянный том/папку `/app/data`.
7. Добавьте переменные:

```text
KIE_API_KEY=<ключ из Kie.ai>
KIE_MODEL=gpt-5-6-luna
PORT=3000
DATA_DIR=/app/data
MOCK_AI=false
```

8. Запустите Deploy. В build logs должны успешно завершиться `npm install`; в runtime logs должна появиться строка о прослушивании `0.0.0.0:3000`.
9. Откройте `https://ваш-домен/health`. Правильный ответ: `{"status":"ok"}`.

Ошибки 502/504 обычно означают, что процесс не запустился, завершился с ошибкой или слушает неверный адрес/порт. Проверьте runtime logs, переменную `PORT`, запуск через `npm start` и наличие `0.0.0.0` в строке старта. Если сайт работает, но Мила показывает сообщение о перерыве, проверьте `KIE_API_KEY`, `MOCK_AI=false`, баланс/логи Kie и опцию Foreign IP.

SQLite хранится в `/app/data/mila.db`, поэтому подключённая постоянная папка должна переживать redeploy. Локально база лежит в `./data/mila.db`.

## Замена рисунков

Основная иллюстрация находится в `public/assets/mila/mila.svg`, маленький портрет — рядом в `mila-avatar.svg`. Их можно заменить своими SVG с теми же именами. Наклейки лежат в `public/assets/stickers/`; сохраняйте прежние имена файлов, чтобы не менять код. Все текущие иллюстрации оригинальные и автономные.

## Обновление сайта

После новых изменений Codex: проверьте `npm test`, отправьте новый коммит в ту же ветку GitHub и нажмите Redeploy в Bothost (или дождитесь автоматического деплоя). Если возникла ошибка, сначала смотрите build logs, затем runtime logs и проверяйте `/health`.
